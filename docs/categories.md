# 主分类与标签目录说明

本库目录体系严格物化网站 `src/lib/config.ts` 的 `TAG_CONFIG`
（本库内 `scripts/config.snapshot.json` 为同步快照，同时是构建脚本的标签树来源）。

## 结构

```
<一级标签>/<二级标签>/<三级标签>/<稿件目录>/
```

- TAG_CONFIG 中每个标签（一 / 二 / 三级）都物化为文件夹；空标签目录以 `.gitkeep` 占位，
  因此新增标签、暂时无稿件的标签都可直接对照 config 找到位置。
- 标签含 `/` 时目录名去斜杠（`逻辑/传输` → `逻辑-传输`、`分流器/黑白名单` →
  `分流器-黑白名单`、`强模 (HSS/OSS)` → `强模 (HSS-OSS)`）。
- 「生产合成」对应 website config 键「生产/合成」；一级键名为 `/` 分隔时目录去斜杠。

## 稿件落位算法（scripts/build.js）

按顺序：

1. 收集稿件 `info.json.tags` 与标签树所有节点的命中项；
2. 取命中的**最深层级**目录（三级 > 二级 > 一级）；
3. 同层级命中多个时，优先父链标签（一级 / 二级）同样命中者（用于区分同名叶子标签，
   如「编码器/二进制」与「解码器/二进制」）；
4. 仍并列则按 TAG_CONFIG 书写顺序取先出现者；
5. 完全未命中（含仅带版本标签 1.16+ / 1.19+ 等）→ 落入「其他杂物」杂项桶。

构建脚本会自动把稿件移动到算法计算出的目录；同一稿件被编辑 tags 后，下一次构建即完成
重新落位并写入 git 历史。

## 其余约定

- 版本标签只参与站点筛选，不作目录维度；`其他杂物` 直接承载无明确二级 / 三级归属的历史稿件。
- 每个稿件目录内 `.meta.json` 由 CI 生成（稳定 `sub-<毫秒>` id + 存档 sha256），人工不要手改；
  `info.json` 为人工编辑的唯一入口。
- 后续调整标签体系时：先改 website `TAG_CONFIG`，再同步本库
  `scripts/config.snapshot.json` 与 README，随后运行 `npm run build` 物化新目录并落位。
